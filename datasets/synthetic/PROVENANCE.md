## What "synthetic" means here

Every record in this file was written by hand by the team. Nothing was
scraped, downloaded, or copied from a third-party corpus, and no record was
produced by running a language model against a real target system.

All the "secrets" that appear in the prompts are placeholders with a
recognisable shape, chosen so that the platform's Blue Team output filters
have something to match:

| Placeholder | Shape it stands in for |
| --- | --- |
| `SYNTH-SECRET-ALPHA99`, `SYNTH-SECRET-ZZZ99`, `SYNTH-SECRET-QQQ42`, `SYNTH-SECRET-BBB77` | a confidential internal token |
| `sk-synth-EXAMPLE01`, `sk-synth-EXAMPLE02` | a synthetic API key |
| `EMP-00000`, `EMP-54321`, `EMP-1…` | a synthetic employee identifier |
| `PROJECT-TITAN` | a fictional internal project codename |
| `BAYORA-CANARY-DEMO` | the demo session canary marker |
| `169.254.169.254` | the IANA-reserved link-local address, used only as the well-known example of a metadata endpoint |

None of these values is a real credential, and no record contains a real
exploit, a real vulnerability identifier, or instructions for compromising
any real system. The attack techniques are described at the level of
*technique category* — the sort of thing a defensive evaluator needs in
order to know what to look for — rather than as a working attack against a
named target.

## External datasets are NOT integrated

The following external corpora were **considered as design references and
deliberately excluded**. No content, no prompts, no labels, no row counts and
no derived statistics from any of them appear in this repository or in the
shipped dataset:

| External dataset | Status |
| --- | --- |
| AdvBench | not integrated |
| JailbreakBench | not integrated |
| HarmBench | not integrated |
| ToxiGen | not integrated |
| Gandalf / Lakera Guardrails | not integrated |
| NVD / CVE records | not integrated |
| DARPA Transparent Computing (AIxCC / ARVO) | not integrated |
| Anthropic HH-RLHF | not integrated |

What *does* exist in the codebase is **importer scaffolding and a provenance
metadata model only** — the `dataset_sources` and `dataset_import_jobs`
tables, the import service in `backend/app/datasets/service.py`, and the
record format that an import would populate. There is no bundled external
dataset content, no download step, and no external corpus is fetched at
runtime. The two rows that `seed_dataset_sources()` inserts describe
*synthetic* sources with synthetic URLs; they are placeholders in the
seeding path and are not the provenance of this file.

If a future version integrates any external corpus, that corpus must be
fetched and reviewed under its own licence, its licence and citation must be
recorded in this file, and the row count and content hash must be recorded
here as well. The MIT licence covering this file does **not** extend to any
external corpus.

## Regenerating the file

The dataset is generated by a script kept alongside it, so that the corpus
can be regenerated and diffed rather than hand-edited:

```sh
python datasets/synthetic/build_dataset.py
```

The script is deterministic: the same source produces a byte-identical file.
A change to the records is a change to the script, and a change to the
script is a change to the version in the table above.

## Verification

The file is JSON Lines: one JSON object per line, UTF-8, no trailing commas.
Each record has exactly these fields:

`case_key`, `title`, `category`, `input`, `expected_outcome`, `is_attack`,
`severity`, `success_condition`, `notes`.

`expected_outcome` is one of `allow`, `block`, `redact`. `is_attack` is
`true` for every category except `benign`.
